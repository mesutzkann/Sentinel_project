# Routing dataset

What the Phase 8 router is trained on and measured against: a question in, the plan it implies
out. Generated by `ai-service/training/routing_dataset.py` from the phrasings in
`ai-service/training/templates.py`; rebuild it with `python -m training.routing_dataset`.

```json
{"id": "R01072", "query": "which class is responsible for the notification sender",
 "language": "en", "source": "template", "template": "which class is responsible for {thing}",
 "intent": "CODE_LOOKUP", "requires_rag": true, "requires_mcp": true,
 "tools": ["source-code-mcp/search_code", "source-code-mcp/read_file"], "target_service": null}
```

| | train | val | test |
|---|---|---|---|
| rows | 1435 | 166 | 225 |
| phrasings per intent | 12–16 | 1–2 | 2–4 |

1826 rows over fifteen intents, 910 English, 807 Turkish and 109 deliberately mixed.

## The two things that decide whether it means anything

**It is not written from the rule router's keyword table.** `routing/rule_router.py` matches
`"slow quer"`, `"deadlock"`, `"connection pool"` and forty more terms. A dataset assembled from
those would make the keyword baseline score close to perfect and Phase 8's claim — that a tuned
1.5B beats a keyword table on the questions people actually ask — would be measured against a
straw man. The phrasings are written as questions; the overlap with the rule table is whatever it
honestly is, and the table scores 0.449 on the test split as a result.

**A phrasing never appears on both sides of the split.** Every fill of one template goes to one
split, so the test set contains phrasings the model has never seen rather than services it has
never seen in a phrasing it knows by heart. Paraphrases inherit their seed's template for the
same reason: a rewrite of a training question is not a test question.

## What is in a row, and where it comes from

`intent` and `target_service` are the label. Everything else — `requires_rag`, `requires_mcp`,
`tools` — is derived from `routing/plans.py`, the same table the planner acts on, so a model
trained on this cannot learn a plan the agent would not execute. `tools` therefore follows from
`intent`, and the benchmark's tool F1 tracks intent accuracy closely rather than measuring
something independent.

`source` is `template`, `typo` or `paraphrase`. Typo'd twins are 10% of the rows: one deliberate
slip each — a doubled letter, a dropped one, a transposition, or a Turkish character typed as its
ASCII cousin — because people type badly under pressure and a router that only works on clean
input works in a demo. Paraphrases are produced by a local 7B and filtered mechanically: a
rewrite that loses the service name or changes language is dropped, because it inherits the
seed's label and a drifted rewrite is a mislabelled row. Asked to rewrite "was orders touched
before this started", the 7B returned Turkish, about conditional payments; both filters caught
it.

## Where the baselines stand

`python -m evaluation.router_eval --split test --models qwen2.5:1.5b-instruct --unconstrained`,
on an RTX 3060 Laptop:

| router | intent | service | tool F1 | invalid JSON | p50 |
|---|---|---|---|---|---|
| rule table | **0.449** | 0.969 | 0.515 | 0% | 0 ms |
| `qwen2.5:1.5b-instruct`, schema enforced | 0.316 | 0.582 | 0.335 | 0% | 1029 ms |
| the same, no grammar | 0.000 | 0.071 | 0.000 | **100%** | 8978 ms |

Three things a tuned model has to answer for:

- **The keyword table is ahead of the prompted 1.5B**, and its service extraction (0.969) is
  nearly perfect because naming a service is a word match rather than a judgement. Beating 0.449
  is the bar; beating 0.969 on services is the harder half.
- **Without the grammar the base model cannot produce the schema at all.** That is the number
  fine-tuning is supposed to move, and constrained decoding hides it — which is why the benchmark
  reports both and the shipped path keeps the grammar on.
- **1029 ms against a 150 ms target.** The prompt carries the fifteen intents and their tool
  lists, which a tuned model would not need. A shorter prompt for the tuned router is the obvious
  lever and it changes the training input, so it is a decision to take before training rather
  than after.
